# RAG 1차 마무리·머지 전 점검 — 2026-10-26

## 범위와 현재 구조

레시피는 배포된 판본의 구조화 값·순서를 조회한다. 상담은 허용된 원문 검색 → 직접 답변 작성 → 근거·수치·질문 대응 검수 → 필요 시 보완 1회로 처리한다. API·JWT·브랜드/역할/판본/시점 필터와 호출·시간 상한은 유지한다. 상세 구조·환경변수·문서 등록 순서는 [RAG README](../README.md)에 모았다.

검수는 문장별 단일 판정·이유·인용 번호를 받고 내부 오류 코드는 서버가 만든다. 작성자의 항목 설명으로 원질문을 덮어쓰지 않는다. 숫자의 연결 메타데이터는 이미 인용한 원문에 동일 값·단위가 명시적으로 유일하게 확인될 때만 보완한다. 값·단위·출처를 새로 만들거나 환산하지 않으며, 모호한 연결과 실제 오류는 계속 거절한다.

답변 작성에는 비교한 B 지침 한 줄을 적용했다. 질문 해결에 필요한 결론·조건·예외는 유지하고 요청하지 않은 배경 의무를 부연하지 않는 지침이다. 이 문구만으로 불필요한 부연이 모두 사라지는 것은 아니다.

## 남겨 둔 한계

- 복잡한 예외 조건을 축약하면서 중요한 조건을 덜 설명할 수 있다. 맞는 핵심 결론에 불필요하거나 범위가 넓은 부연이 붙는 사례도 확인했다.
- 답변에 직접 쓰이지 않은 관련 자료가 출처에 섞일 수 있다.
- 동일 질문·표현 변형에 대한 재현성과 모델의 의미 검수는 완전히 보장되지 않는다. 더 많은 검수 단계를 붙이는 것을 완료 조건으로 삼지 않는다.
- 다단계 법령 참조·개정 시점·충돌·예외 우선순위의 종합 판단은 다음 단계 과제다. 시행일 미검수 경고는 남긴다.
- 레시피 v1.0의 이전 시연 결과를 v1.1 승인·배포 이후의 동작 보장으로 확대하지 않는다.
- 이번 점검에 브라우저 레이아웃·녹음과 선택 Voice AI의 전체 E2E는 포함하지 않았다.

## 머지 전 정리

- 사용하지 않는 규정 카드 엔진·JSON·전용 계약·별도 완료 상태·전용 검사를 제거했다. 원본 문서와 FAISS 색인은 삭제하지 않았다.
- 표 선택 경로와 셀 복원을 `table_evidence.py`로 통합하고 관련 검사도 `test_table_evidence.py`로 모았다.
- 현재 모델이 출력하지 않는 비교 설명/누락 목록 호환 코드와 그 전용 검사, 사용하지 않는 인자·필드를 제거했다. 실제 조건 누락·대상 확대·인용 오류 검사는 유지한다.
- 문서는 구조·운영용 README와 이 점검 요약으로 정리했다. 전체 중간 이력은 로컬 백업에 보존했다.
- 정리 전후 실제 작성·검수 모델의 JSON Schema가 같음을 대조했다. 정상 답변·근거 부족·검수 거부의 오프라인 공개 응답과 호출 순서도 동일했다. 실제 모델의 모든 답변이 영구히 동일하다는 뜻은 아니다.
- 정리 후 `pytest rag/tests -q`: **391개 통과·3개 건너뜀**. 건너뛴 3개는 별도 `FRANGIZER_JAVA_CP` 설정이 필요한 실제 Java JWT 연동 검사다. 공개 API 계약·권한·색인 경계·기본 실행 검사도 포함했고, 이 테스트에서 실제 모델 API는 호출하지 않았다.

정리 전 파일 24개는 내용을 대조한 뒤 로컬 `rag/.demo/archive/2026-10-26-premerge-cleanup.zip`에 보관했다. `.demo`는 Git과 Docker 빌드에서 제외된다. 과거 실제 응답·진단은 그 아래의 `verdict-fix/`, `brief-ab-only/`, `new-topics-20261026/`에 있고, 정리 검사는 `premerge-cleanup/`에 보관한다. 로컬 중간 산출물을 머지 대상으로 삼지 않는다.

## 실행·확인

기존 문서·DB·환경이 준비된 상태에서 RAG 변경만 반영:

```bash
cd /Users/inwoopark/workspace/ai-service/ai-service-project/frangizer
docker compose up -d --no-deps --build rag
open http://localhost
```

마지막 정리 자체에는 문서 재등록·시드·재색인이 필요 없다. 다만 함께 배포하는 `chunker-v6-context` 상위 문맥 임베딩과 구조화 표 필드를 기존 자료에 적용하려면 새 revision으로 재색인해야 한다. [README의 재색인·팀 공유 안내](../README.md)를 따른다. 새로운 저장소에서 처음 실행하는 경우는 문서 등록·승인·배포 절차가 필요하다. 정리 과정에서 다른 담당자의 backend·frontend·data와 루트 배포 설정은 수정하지 않았다. 기존 색인 연동 변경은 RAG 기능 적용에 필요해 함께 배포한다.
