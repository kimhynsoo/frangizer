
## 3. 색인 작업이 하는 일 (`run_index_job`)

입력은 `IndexJobRequest`(계약 그대로, 추가 필드 거부)이고 반환은 `IndexJob`이다. B의 라우터는 이 함수를 백그라운드로 부르고, 서버 시작 시 `JobStore(FAISS_DIR).recover_interrupted()`를 한 번 호출하면 된다.

경로 기본값(C 회신): 볼륨 하나를 backend·rag 모두 `/var/lib/frangizer`에 마운트한다. `DOCUMENT_STORE_DIR=/var/lib/frangizer`, `FAISS_DIR=/var/lib/frangizer/faiss`. 저장 키는 `documents/{document_id}/{version_id}.pdf`이다.

1. 저장 키 → `DOCUMENT_STORE_DIR` 안의 실제 파일. `..`·빈 구간·루트 밖 심볼릭 링크 거부
2. sha256 대조 → 불일치 `CHECKSUM_MISMATCH`
3. 쪽 정책 검증(범위 밖·포함/제외 충돌·남는 쪽 없음) → 추출 → 분할
4. 임베딩 → `FAISS_DIR/revisions/.tmp-…`에 작성 → 검증 → 이름 바꿔 확정
5. 같은 `job_id`+같은 내용은 기존 결과, 다른 내용은 `JobConflict`(→ 409)

`index_revision`은 판본·파일 해시·쪽 정책·분할 버전·임베딩 모델·메타데이터로 정해진다. 같은 입력은 같은 revision을 재사용하고 덮어쓰지 않는다. 하나라도 바뀌면 새 revision이 생긴다. 실패하면 임시 디렉터리를 지우고 기존 revision은 그대로 둔다.

### 실패 코드 (`IndexJob.error_code`)

계약은 `CHECKSUM_MISMATCH`만 명시한다. 아래 목록은 C가 채택했고(2026-10-23), 백엔드는 `error_code`를 그대로 전달한다.

| 코드 | 의미 |
| --- | --- |
| `CHECKSUM_MISMATCH` | 파일 해시가 요청과 다름 |
| `INVALID_STORAGE_KEY` / `SOURCE_NOT_FOUND` | 저장 키가 루트를 벗어남 / 파일 없음 |
| `PAGE_POLICY_INVALID` | 쪽 정책 오류 |
| `EXTRACTION_FAILED` | 열 수 없음·모든 쪽 스캔본·조각 0개 |
| `ARTICLE_PERIOD_CONFLICT` | 문서 적용일 전에 끝나는 조문이 생김 |
| `EMBEDDING_NOT_CONFIGURED` / `EMBEDDING_FAILED` | 모델 미설정 / 호출 실패 |
| `INDEX_VALIDATION_FAILED` | 건수·차원·해시·ID·판본 연결 검증 실패 |
| `INTERRUPTED` | 서버 재시작으로 중단(C 제안). C가 새 job_id로 재색인 |
| `INTERNAL_ERROR` | 그 밖의 오류(내부 경로는 남기지 않음) |

## 4. 산출물 형식 (A·B·E 합의용 제안)

`FAISS_DIR/revisions/{index_revision}/`

| 파일 | 내용 |
| --- | --- |
| `index.faiss` | `IndexFlatIP`, L2 정규화 벡터. i번째 벡터 = `chunks.jsonl` i번째 줄 |
| `chunks.jsonl` | 줄마다 `{"metadata": IndexedChunkMetadata, "heading": str, "text": str}` |
| `build-manifest.json` | 입력 해시·쪽 정책·분할 버전·모델·차원·건수·`chunk_ids` 순서 |
| `quality-report.json` | 쪽별 글자 수·제거한 머리말 수·표 수·경고 |

작업 기록은 `FAISS_DIR/jobs/{job_id}.json`. 단일 프로세스 가정이며, 재시작 시 `running`으로 남은 작업은 `failed` + `INTERRUPTED`로 바꾸고 남은 임시 디렉터리를 지운다.

`metadata`는 계약의 `IndexedChunkMetadata`만 담고(추가 필드 없음), 본문은 바깥 `text`에 둔다. 테스트에서 계약 YAML로 직접 검증한다.

### 조각 ID (B와 합의 필요)

| 필드 | 형식 | 예 |
| --- | --- | --- |
| `section_key` | 조 `art-{조}[-{의}]`, 부칙 `add{n}-art-…`, 쪽 `p{쪽}`, 나눈 경우 `.p{n}`/`.{n}`, 시행 예정본 `-from{YYYYMMDD}` | `art-12-2-from20261231` |
| `chunk_id` | `chk-{revision 일부 12자}-{section_key}`. 100자를 넘으면 section_key를 해시로 줄임(자르지 않음). 원본 14개 전체에서 100자 이하·중복 없음 확인 | `chk-3f2a…-art-17` |
| `article` | 원문 표기 | `제12조의2`, `부칙1 제1조` |
| `page` | 조각이 시작하는 PDF 파일 쪽(1부터) | `5` |

## 5. 분할 규칙과 로컬 검수 결과

| 자료 | 분할 | 결과 |
| --- | --- | --- |
| 법령·고시 본문 | 조 단위, 긴 조는 항(①…) 경계에서 나누고 조 제목을 다시 붙임. 장·절 제목은 본문에서 빼고 조 제목 맥락으로 | 조문형 8개(식품위생법·시행령·시행규칙, 가맹사업법·시행령, 소비자기본법, 소비자분쟁해결기준, 전자상거래법 발췌) 조 단위 |
| 별표·지침·표 | 쪽 단위(1,500자 안팎에서 줄 경계로 나눔). 별표 파일의 부칙은 조 단위 | 심사지침, 두 별표 파일 |
| 정보공개서 | 쪽 단위 | 처리한 58쪽 중 40쪽에 표 |
| 합성 계약서 | 조 단위 | 53개 조 |
| 레시피 | 쪽(메뉴) 단위 | 8쪽 |

**시행 예정 조문 처리.** 법제처 출력본은 시행 전 개정 조문을 현행 조문 뒤에 다시 싣고 끝에 `[시행일: 2026. 12. 31.] 제12조의2` 같은 꼬리표를 붙인다. 그대로 색인하면 아직 시행되지 않은 조문이 현행처럼 검색된다. 꼬리표 기준으로 시행 예정본은 그 날부터, 앞의 현행본은 그 날까지로 조각 적용 기간을 나눴다. 현행본 없이 조 전체를 가리키는 꼬리표는 시행 예정 신설 조문으로 본다.

| 문서 | 자동 분리한 조문 |
| --- | --- |
| 식품위생법 | 28 |
| 가맹사업법 | 9 |
| 가맹사업법 시행령 | 3 |
| 식품위생법 시행령 | 2 |

`legal_temporal_reviewed`는 전부 `false`다. 위 처리는 출력본 표기를 기계적으로 읽은 것이며 경과규정·부칙 검토를 대신하지 않는다. C 결정(2026-10-23): 자동 분리 방식을 채택하고, `false`여도 검색을 허용하되 B가 답변에 "시행일 미검수"를 표시한다.

**표.** 정보공개서·소비자분쟁해결기준 별표의 표는 PyMuPDF 셀 추출에서 숫자가 칸 사이로 끊긴다(예: `68272\n,`). 지금은 줄 단위 텍스트만 넣고 표가 있는 쪽을 `TABLE_NEEDS_REVIEW`로 보고한다. 비용표 질문(예: 임대보증금 포함 여부)은 원문 대조가 필요하다.

스캔본으로 보이는 쪽은 없다.

## 6. 레시피 구조화 자료

메뉴 7종, 메뉴·온도·판본 14건, 공통 규칙 12개. 값·단위는 원문 문자열 그대로이고 단위·펌프 환산을 하지 않았다. 내용이 바뀐 메뉴만 새 판본 건을 만든다(바닐라라테 HOT·ICED 20→15 mL, 허니자몽블랙티 v1.1 신규). PDF 줄바꿈 자리의 띄어쓰기는 텍스트로 알 수 없어 11곳을 사람이 검수해 3곳만 띄웠다(`review.wrap_joins`).

이 자료는 현행 시나리오(20→15 mL, 2026-10-26 0시)를 따르며, C가 이 시나리오에 동의했다. 이전 합성 데이터(20→25 ml, 메뉴 50종)는 쓰지 않는다.

**쓰임(C 회신).** MVP에서 레시피도 `/rag-query`로 답하고 RDB 적재는 하지 않는다. 조리 중 단계·양 질문의 응답 속도가 문제되면 B가 RAG 내부에서 이 파일로 LLM 없이 답할 수 있다. 응답 형식·출처는 그대로라 백엔드·화면은 바뀌지 않는다. 연결할 때 쓰는 키는 다음과 같다.

- 검색된 레시피 조각의 `page`(PDF 파일 쪽)와 판본 → `recipe_versions[].sources[]`의 `document_version`·`page`
- 질의 시점 → `effective_from ≤ as_of < effective_until`(null은 종료 없음)
- 메뉴·온도 → `menu_id`·`temperature`. 직전 6턴 대화로 "아까 그 메뉴"를 해석하는 것은 B 몫이다.
