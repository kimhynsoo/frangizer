## 1. `docker compose up -d`로 전체 기동 — ✅

| 확인 | 근거 |
| --- | --- |
| 명령 하나로 5개 서비스 기동 | `docker compose up -d --build` → db, backend, rag, voice, web |
| 기동 상태 | `docker compose ps`: db·backend·rag `healthy`, voice·web `Up` |
| 기동 순서 | 헬스체크 기반 `depends_on`: db → backend·rag → web |
| 처음 받은 환경에서 재현 | 별도 프로젝트 이름·새 볼륨으로 빌드 → 시드 13건 → `scripts/smoke.sh` 7개 항목 통과 (10/23) |
| 데이터 준비 | `scripts/seed_documents.py --apply --publish`로 원본 13건 등록·색인·배포, 실패 0건 |

## 2. 서비스 간 호출은 서비스 이름으로 — ✅

| 호출 | 설정 (`docker compose config`) |
| --- | --- |
| backend → db | `DB_URL: jdbc:mariadb://db:3306/frangizer` |
| backend → rag | `RAG_URL: http://rag:8001` |
| backend → voice | `VOICE_URL: http://voice:8008` |
| web → backend | nginx `proxy_pass http://backend:8080` (`/api/`) |

`localhost`를 쓰는 값은 `.env.example`의 로컬 `bootRun`용뿐이며, compose가 서비스 이름으로 덮어씁니다. rag 로그에서 backend 컨테이너가 보낸 `POST /rag-query`를 확인했습니다.

## 3. LLM 키·JWT 비밀키는 `.env`로만 주입 — ✅

| 확인 | 근거 |
| --- | --- |
| 값 주입 경로 | compose가 `.env`의 값을 `${변수}`로 읽어 환경변수로 전달 |
| 필수값 누락 방지 | `DB_PASSWORD`, `JWT_SECRET`, `INTERNAL_TOKEN`, `DEMO_PASSWORD`가 비면 기동 전에 안내 후 중단(`${변수:?…}` 8곳) |
| Git에 `.env` 없음 | `git ls-files`에 `.env` 0건. `.gitignore`가 `.env`, `.env.*` 제외(`.env.example`만 추적) |
| 저장소에 실제 키 없음 | `sk-` 형식 문자열 1건은 `rag/tests/test_preflight.py`의 테스트용 가짜 값(키를 모델 칸에 넣으면 거부되는지 검사). 실제 `.env`의 키와 다름 |
| 이미지에 `.env` 없음 | backend·rag·voice·web 이미지 안 `.env` 파일 0건 (`.dockerignore`) |
| 비밀값이 아닌 설정 | 토큰 단가(`LLM_PRICE_INPUT_PER_1M`, `LLM_PRICE_OUTPUT_PER_1M`, `EMBEDDING_PRICE_PER_1M`)는 비밀값이 아니므로 compose 기본값(`gpt-5.4-mini`)을 두고 `.env`로 바꿀 수 있게 함 (`feat/backend-token-logging` PR) |
