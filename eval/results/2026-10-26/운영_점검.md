## 2. 토큰 비용

### 단가 (`gpt-5.4-mini`, 100만 토큰 기준)

| 구분 | 단가 |
| --- | --- |
| 입력 | $0.75 |
| 캐시된 입력 | $0.075 |
| 출력 | $4.50 |

출처: OpenAI API 단가, 2026-10-26 팀 확인. 임베딩(`text-embedding-3-small`)은 질문당 약 20토큰이라 계산에서 제외했고, 문서 색인 때의 임베딩은 1회성 비용이라 별도입니다.

### 측정한 토큰 사용량

| 질문 유형 | 측정 건수 | 입력 토큰 | 출력 토큰 |
| --- | --- | --- | --- |
| 구조화 레시피 (LLM 없음) | 2 | 0 | 0 |
| LLM 상담 | 7 | 평균 75,191 (최대 109,076) | 평균 929 |
| 시간 초과 | 1 | 기록 없음 | 기록 없음 |

### 요청당 원가

```
요청당 원가 = 입력 토큰 × $0.75/100만 + 출력 토큰 × $4.50/100만
LLM 상담 평균 1건 = 75,191 × 0.00000075 + 929 × 0.0000045
                 = $0.05639 + $0.00418 = 약 $0.061
```

| 구분 | 1건 원가 |
| --- | --- |
| LLM 상담 평균 | **약 $0.061** (입력 $0.056 + 출력 $0.004) |
| LLM 상담 최소 ~ 최대 | $0.043 ~ $0.088 |
| 구조화 레시피 | $0 |
| 입력이 모두 캐시 단가로 처리될 때 (하한) | 약 $0.010 (84% 절감) |
| 측정 10건 합계 | 약 $0.42 |

비용의 93%가 **입력 토큰**에서 나옵니다. 질문 하나에 검색 문맥과 근거 검수용 입력이 평균 7.5만 토큰 들어가기 때문입니다.

### 월 예상 비용

가정: 월 30일, 질문의 70%가 LLM 상담(측정 비율), 1건 $0.061. 캐시 적중률은 확인하지 못해 "캐시 없음"을 기준으로 하고, 전부 캐시될 때를 하한으로 함께 적습니다.

| 시나리오 | 점포 수 | 점포당 하루 질문 | 월 질문 | 월 LLM 호출 | 월 입력 토큰 | **월 비용** | 하한(전부 캐시) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 시연 기업 (가맹카페 A) | 12 | 10 | 3,600 | 2,520 | 1.9억 | **약 $153** | 약 $25 |
| 소형 브랜드 | 50 | 20 | 30,000 | 21,000 | 15.8억 | **약 $1,272** | 약 $206 |
| 중형 브랜드 | 300 | 20 | 180,000 | 126,000 | 94.7억 | **약 $7,632** | 약 $1,237 |

### 원가를 줄이는 방법

| 방법 | 근거 |
| --- | --- |
| 구조화 답변 범위 넓히기 | 레시피 구조화 답변은 토큰 0, 0.03초. 자주 묻는 질문을 이 경로로 보내면 비용·지연이 함께 줄어듦 |
| 검색 문맥과 검수 입력 줄이기 | 비용의 93%가 입력. 검색 후보 수와 문맥 길이 상한을 낮추면 바로 줄어듦 |
| 검수·재순위화 호출 횟수 제한 | 한 질문 안에서 LLM을 여러 번 부름 |
| 캐시 활용 | 같은 시스템 프롬프트·문맥이 반복되면 캐시 단가($0.075)가 적용되어 입력 비용이 최대 90% 감소 |
| 같은 질문 결과 재사용 | RAG의 질의 결과 재사용(`RAG_STATE_DB`)으로 동일 질문은 LLM을 다시 부르지 않음 |

측정 시점에는 질문마다 토큰이 `question_events.rag_meta.usage`에 기록됐지만 `estimated_cost_usd`는 비어 있었습니다. 이를 보완해 `feat/backend-token-logging` PR에서 단가 설정(`LLM_PRICE_INPUT_PER_1M`, `LLM_PRICE_OUTPUT_PER_1M`)으로 요청당 비용을 계산해 `estimated_cost_usd`를 채우고 요청 로그에도 함께 남기도록 했습니다(아래 3. 로깅).

## 3. 로깅

### 측정 시점

| 항목 | 결과 |
| --- | --- |
| backend 요청 로그 | `request_id, method, path, status, latency_ms, user`만 기록. 질문 원문 없음. **토큰은 로그에 없음** |
| rag 로그 | 질문 원문 없음 |
| 질문 기록(DB) | 마스킹된 질문(`question_redacted`)과 상태·지연·토큰 사용량(`rag_meta.usage`) 저장, 추정 비용은 비어 있음 |

### 보완: 지연·토큰 로그 미들웨어 (`feat/backend-token-logging` PR, C 리뷰 대기)

교재의 "지연·토큰 로그 미들웨어"와 같은 방식으로, 모든 요청을 감싸는 기존 필터(`RequestIdFilter`)에 토큰 사용량을 붙였습니다. RAG를 거친 요청은 백엔드가 받은 `usage`를 요청 속성에 담고, 필터가 요청이 끝날 때 같은 줄에 출력합니다.

```
path=/api/v1/rag-query status=200 latency_ms=11278 user=user-demo-01 question_id=q-… reused=false llm=true in_tok=114437 out_tok=1078 emb_tok=73 model=gpt-5.4-mini cost_usd=0.09068
```

| 경우 | 로그 |
| --- | --- |
| LLM 상담 | 입력·출력·임베딩 토큰, 모델, 추정 비용 |
| 구조화 레시피 (LLM 미호출) | `llm=false`, 토큰 0, 비용 0 |
| 같은 Idempotency-Key 재전송 | `reused=true`, 토큰 0 (RAG 미호출) |
| 로그인 등 RAG 미경유 요청 | 기존 항목만 |

질문 원문은 로그에 남기지 않으며, 추정 비용은 DB `rag_meta.usage.estimated_cost_usd`에도 저장됩니다. 실제 질문으로 로그 비용($0.09068)과 직접 계산값(114,437 × $0.75/100만 + 1,078 × $4.50/100만)이 일치함을 확인했습니다.
