## 2. 토큰 비용

### 단가 (`gpt-5.4-mini`, 100만 토큰 기준)

| 구분 | 단가 |
| --- | --- |
| 입력 | $0.75 |
| 캐시된 입력 | $0.075 |
| 출력 | $4.50 |

출처: OpenAI API 단가, 2026-10-26 팀 확인. 임베딩(`text-embedding-3-small`)은 질문당 약 20토큰이라 계산에서 제외했고, 문서 색인 때의 임베딩은 1회성 비용이라 별도입니다.

### 측정한 토큰 사용량

| 질문 유형 | 측정 건수 | 입력 토큰 | 출력 토큰 |
| --- | --- | --- | --- |
| 구조화 레시피 (LLM 없음) | 2 | 0 | 0 |
| LLM 상담 | 7 | 평균 75,191 (최대 109,076) | 평균 929 |
| 시간 초과 | 1 | 기록 없음 | 기록 없음 |

### 요청당 원가

```
요청당 원가 = 입력 토큰 × $0.75/100만 + 출력 토큰 × $4.50/100만
LLM 상담 평균 1건 = 75,191 × 0.00000075 + 929 × 0.0000045
                 = $0.05639 + $0.00418 = 약 $0.061
```

| 구분 | 1건 원가 |
| --- | --- |
| LLM 상담 평균 | **약 $0.061** (입력 $0.056 + 출력 $0.004) |
| LLM 상담 최소 ~ 최대 | $0.043 ~ $0.088 |
| 구조화 레시피 | $0 |
| 입력이 모두 캐시 단가로 처리될 때 (하한) | 약 $0.010 (84% 절감) |
| 측정 10건 합계 | 약 $0.42 |

비용의 93%가 **입력 토큰**에서 나옵니다. 질문 하나에 검색 문맥과 근거 검수용 입력이 평균 7.5만 토큰 들어가기 때문입니다.

### 월 예상 비용

가정: 월 30일, 질문의 70%가 LLM 상담(측정 비율), 1건 $0.061. 캐시 적중률은 확인하지 못해 "캐시 없음"을 기준으로 하고, 전부 캐시될 때를 하한으로 함께 적습니다.

| 시나리오 | 점포 수 | 점포당 하루 질문 | 월 질문 | 월 LLM 호출 | 월 입력 토큰 | **월 비용** | 하한(전부 캐시) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 시연 기업 (가맹카페 A) | 12 | 10 | 3,600 | 2,520 | 1.9억 | **약 $153** | 약 $25 |
| 소형 브랜드 | 50 | 20 | 30,000 | 21,000 | 15.8억 | **약 $1,272** | 약 $206 |
| 중형 브랜드 | 300 | 20 | 180,000 | 126,000 | 94.7억 | **약 $7,632** | 약 $1,237 |

### 원가를 줄이는 방법

| 방법 | 근거 |
| --- | --- |
| 구조화 답변 범위 넓히기 | 레시피 구조화 답변은 토큰 0, 0.03초. 자주 묻는 질문을 이 경로로 보내면 비용·지연이 함께 줄어듦 |
| 검색 문맥과 검수 입력 줄이기 | 비용의 93%가 입력. 검색 후보 수와 문맥 길이 상한을 낮추면 바로 줄어듦 |
| 검수·재순위화 호출 횟수 제한 | 한 질문 안에서 LLM을 여러 번 부름 |
| 캐시 활용 | 같은 시스템 프롬프트·문맥이 반복되면 캐시 단가($0.075)가 적용되어 입력 비용이 최대 90% 감소 |
| 같은 질문 결과 재사용 | RAG의 질의 결과 재사용(`RAG_STATE_DB`)으로 동일 질문은 LLM을 다시 부르지 않음 |

시스템은 질문마다 토큰을 `question_events.rag_meta.usage`에 기록하지만 `estimated_cost_usd`는 비어 있습니다. 단가를 설정값으로 받아 이 값을 채우면 운영 중에도 비용을 바로 확인할 수 있습니다(B·C 후속).
